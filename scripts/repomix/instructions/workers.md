# Repomix Instruction: Cloudflare Workers Context

This pack contains the Cloudflare Workers source for IntegrityStudio.ai — the four deployed
Workers, the local receiver stub, the shared `workers/lib/` package, and each package's deploy
and test configuration. Use it when changing worker routes, bindings, schemas, or deployment
config. Tests are **not** here — they are in `tests-compressed.xml`.

## What Is Included

| Path | Contents |
|------|----------|
| `workers/lib/` | Shared auth, api-keys, billing, entitlements, crypto, Supabase client, Zod schemas |
| `workers/api-gateway/src/` | Routes (`/v1/*`, `/bootstrap`), quota Durable Object, usage ledger, aggregation |
| `workers/sender-worker/src/` | `/signup`, `/signin`, `/send`, `/create-checkout-session`; HMAC-signs to the receiver |
| `workers/stripe-webhook/src/` | Stripe event handlers, dead-letter, Supabase sync |
| `workers/contact-form/src/` | Contact form (Resend, KV rate limit, CSRF, idempotency) |
| `workers/receiver-worker/src/` | Local stub / test double only — never deployed |
| `workers/*/wrangler.toml` | Top-level block = production; `[env.dev]` = dev overlay |
| `workers/*/vitest*.config.*` | Which suite runs when; sender-worker's e2e bindings live in `vitest.e2e.config.mts` |
| `workers/docs/`, `workers/*/README.md`, `workers/lib/TYPES.md` | Design notes |

## Excluded

- `*.test.ts` (see `tests-compressed.xml`), `*.d.ts` (generated by `wrangler types`)
- lockfiles, `coverage/`, `dist/`, `.wrangler/`, `node_modules/`
- every `.env*` file and `.claude/` — credentials never belong in a pack

## Rules That Bite (full detail in CLAUDE.md)

- `deploy:prd` never passes `--env`; a named environment renames the Worker and orphans its DOs, routes, and crons.
- Bindings are **not** inherited into `[env.dev]` — repeat them. `routes` and `triggers` **are** — set `routes = []` and `crons = []` there.
- `sender-worker` deploys via CI on merge to `main`; a manual `deploy:prd` gets rolled back by the next stale-`main` CI run.
- `SHARED_SECRET` is retired (CR29): `SIGNING_KEYS` + `ACTIVE_KEY_ID` are the only signing credential and `x-key-id` is sent unconditionally.
- `/create-checkout-session` derives the org from the email server-side — never from the request body.
- `api-gateway` verifies Auth0 JWTs against Auth0 JWKS; `SUPABASE_JWT_SECRET` is deliberately unbound.
- Not workspaces: audit and bump dependencies **per package**; lockfiles are gitignored so declared floors are the only control.
